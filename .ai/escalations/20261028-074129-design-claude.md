## Recommendation

### 1. Storage: no autosave until the first real edit, with a one-deep checkpoint

At boot, never write. Read `KEY`, and if it parses, keep the raw string as `ui.resumeRaw` and enable **Continue**. Then build the fresh planted field. Remove `scheduleSave()` at `game.js:1580`. The invalid-save backup at `:1568-1570` can stay unchanged.

Add `ui.ownsSave = false`. In `scheduleSave`, before the first write of the session:

```js
if (!ui.ownsSave) {
  var prev = load(KEY);
  if (prev && prev !== ui.lastWritten) {
    if (load(PREV_KEY) !== prev && !store(PREV_KEY, prev)) { ui.saveBlocked = true; /* existing paused message */ return; }
  }
  ui.ownsSave = true;
}
```

Only the edit path (`changed()` at `:1011`) and explicit actions (`newField`, import, Continue) may set `ownsSave`. Several callers currently save when nothing has been carved: name (`:1456`), season (`:1466`), animal (`:1471`) and `toggleMaze` (`:1187`). Until `ownsSave` is true, those calls must not write the field. Store "last size/season/animal" in a small separate prefs key. **This is the overwrite to watch for:** today, changing the animal on a fresh field would silently replace the saved carving.

**Continue** loads `ui.ownsSave ? load(PREV_KEY) : ui.resumeRaw`:
- If the current field has edits, show a confirmation first (reuse the import confirm at `:1298`).
- Clear the pending `ui.saveTimer`.
- Write the restored state to `KEY` straight away, so a reload offers what the user picked.

Import follows the same rules.

**Tradeoff:** only one checkpoint is kept. If the user carves fresh fields in two sessions in a row, the oldest save is gone. State this next to Continue ("Starting a new carving keeps only your last field"). The alternative is a ring of N slots with a picker: safer, but more UI and more quota pressure.

**Risk:** two open tabs can still race on `KEY`. Note this rather than fix it now.

**Tests:**
- Booting writes nothing to `KEY` (spy on `setItem`).
- Season, animal or name changes write nothing.
- The first carve leaves `PREV_KEY === old` before `KEY` changes.
- A quota failure on `PREV_KEY` blocks saving and keeps the old save.

### 2. Gait
- Change `G.phase += d*TAU` (`:939`) to `d*TAU*0.4`.
- When the runner stops, ease the phase to the nearest multiple of π, not to 0.
- Draw the lower legs **outside** the body outline, at least `max(2px, 0.08t)`.
- Work out `ui.reduce` from the Device/Full/Reduced preference, and listen for changes to the media query.
- The pose tests should compare `getImageData` in Full mode at phase 0 and at phase π/2.

### 3. Corn sway
- Split the cached layer: ground and soil stay in `ui.layer`, and corn comes out of it.
- Render about 4–6 stalk variants per season into an atlas. Rebuild it only when `layerDirty` or the zoom changes.
- For visible cells only, draw with a horizontal **skew anchored at the stalk base**: `setTransform(s,0,k,s,x,baseY)` with `k = 0.04·sin(ωt + hash(cell))`. With skew the roots stay exactly in place. Rotation shifts them, and skew is cheaper.
- Reduced mode and PNG export use a baked static corn layer, so the existing pixel-idle test still passes.
- **Risk:** large fields that are zoomed out. If the visible cell count goes over a threshold, quantise the sway phase and redraw every other frame.

### 4. Audio rotation
`hushMusic` (`audio.js:130`) rewinds `beat`. So **don't** advance the track with a mutable counter at scheduling time. Work it out from the beat number:

```js
function trackAt(b) { return prefs.auto ? (baseTrack + Math.floor((b - baseBeat) / PHRASE)) % 5 : baseTrack; }
```

- Here `PHRASE = 4*LOOP_STEPS`. `scheduleStep(beat, t)` calls `patternAt(beat, trackAt(beat))`, so a rewind also restores the right track.
- A manual pick calls `hushMusic()`, then sets `baseTrack = sel` and `baseBeat = beat`.
- Selecting while muted only updates `prefs`. It never calls `ensure()`.
- Update "now playing" at the time it is heard, with `setTimeout(nextBeat - now)`, not when it is queued.
- `patternAt(step)` with no track argument must return the original track, identical to today. Test this with a deep-equality check against a snapshot captured before the change.
