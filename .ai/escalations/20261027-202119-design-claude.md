## Recommendation: keep `game.js` as one classic script with a pure core and a thin shell

Split `game.js` into two sections inside the same file:

- **Core:** pure functions over plain data. `createField`, `carve`, `undo`, `validateMap`, `serialize`, `deserialize`, plus a seeded RNG.
- **Shell:** canvas, DOM, input and storage. It runs only when `typeof window !== 'undefined'`.

Export the core with a UMD-style tail: `if (typeof module === 'object') module.exports = Core; else window.CozyCore = Core;`.

**Why:** "Offline" usually means someone double-clicks `index.html`. On `file://`, ES modules are blocked by CORS in Chrome and Edge, so a classic `<script src>` is the only zero-tooling option that works. It also loads directly into `tests/game.test.cjs` with `require` and no bundler.

**Main tradeoff:** a single file grows large and the core/shell boundary is only a convention. To keep it honest, add a test that loads the core under Node with `window`, `document` and `localStorage` undefined.

**Alternative worth considering:** two scripts, `core.js` and `game.js`. This makes the boundary physical and suits future ports better. It's a fifth file, which is over the plan's four-file cap. I'd accept that if the core goes past about 400 lines.

## Essential safeguards for the sharing boundary

1. **Versioned envelope:** `{format:"cozy-fieldwork", v:1, size, season, runner, grid}`. Reject an unknown `format` and any `v` newer than this build supports. Add explicit migrators for older versions, `v → v+1`, in the core.
2. **Validate before touching state.** Allowlist the enum values for size, season and runner. Check that the grid dimensions exactly match the chosen size preset, and that every cell is in the allowed range. Ignore unknown keys and never spread them into state.
3. **Bounds:**
   - Check the file or text length before calling `JSON.parse`. About 256 KB is ample.
   - Cap grid cells, with the maximum preset as the ceiling.
   - Reject `__proto__`, `constructor` and `prototype` keys. Build state from new literals instead of using `Object.assign` on parsed input.
4. **Grid encoding:** store the grid as a compact string or RLE, not a nested array. That keeps it small, easy to validate (a regex or charset check) and stable for ports.
5. **No HTML injection:** use `textContent` only, never `innerHTML`, for anything that comes from a file or a save, such as names or titles.
6. **Image export:** use `canvas.toBlob` and an object URL, then call `revokeObjectURL`. Because the art is procedural, there's no tainted-canvas risk; keep it that way by never drawing external images. Fall back to `toDataURL` for old Safari.
7. **Local saves:**
   - Wrap `localStorage` in try/catch. It throws in Safari private mode, on some `file://` origins, and when quota is exceeded. Degrade to in-memory saving with a visible notice.
   - Save with the same envelope and validator as shared files, so one code path handles both.
   - Namespace the key, e.g. `cozyFieldwork.v1.slot0`.
8. **Undo:** keep a bounded stack (about 100 entries) of diffs or grid snapshots, and clear it when a map is loaded.
9. **Determinism:** generate maze content and runner AI from a seeded RNG stored in the save. Shared maps then replay the same way, and tests can be deterministic.

## Portability decisions

- Use Pointer Events for mouse, touch and pen in one path. Set `touch-action: none` on the canvas.
- Scale the canvas backing store by `devicePixelRatio`.
- Run the simulation on a fixed timestep with interpolated rendering, so speed doesn't depend on refresh rate (60, 120 or 144 Hz).
- Draw from model state in grid units and convert to pixels only in the renderer. Future ports can then reuse the core unchanged.
- Accessibility:
  - Keyboard controls: arrows or WASD, with Enter or Space to carve.
  - An `aria-live` region for game events.
  - Real `<button>` elements, not canvas hit zones, for menus.
  - Respect `prefers-reduced-motion`.

## Risks to existing work

- `original.html` stays untouched as a reference, so there's no regression risk there.
- `.agent.env` `TEST_CMD` should be `node tests/game.test.cjs`, which works the same in PowerShell and Git Bash. Avoid Linux-only globs in it.
