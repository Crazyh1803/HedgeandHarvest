I recommend six changes, one per area below. None of them touches `audio.js`'s song data, the storage keys or the serialized fields.

**1. Corn: split plants only for stalks that are moving**
- Add a pure sampler `cornPose(x, y, plant, seed, time) → {angle, active}` to the core export so Node tests can call it. Give each plant its own seeded period (8–15 s), offset and burst length (1.5–2.5 s). The burst envelope is `sin²(πu)`, so it starts and stops smoothly. Peak lean is 5–8°. A ~2 s burst every ~11.5 s means about 17% of plants are active at once, within the 8–20% target.
- In `getSprites` (`game.js:579`), render each variant's three plants into separate canvases, using the same `rnd` call order so they look identical to today. The shadow gets its own canvas. Then build the composite cell sprite by drawing those layers onto it, not by redrawing the plants, so the two always match pixel for pixel.
- In `drawCorn` (`game.js:671`), draw cells where all three plants are idle with the composite (one `drawImage`). Only active cells draw shadow, back-left, back-right, front, each rotated about its own root. Rotation reads better than skew at 8°, and skew visibly stretches the leaves.
- **Pitfalls:**
  - Large fields in fit view could mean 10k+ `drawImage` calls per frame on phones. Fall back to the baked layer when `t` is below about 10 px, because motion isn't visible at that size anyway.
  - `spriteCache` holds a single entry and rebuilds on every zoom or DPR change. That's fine, but keep the plant canvases cropped. Full-size canvases ×24 at DPR 3 adds real memory pressure on iOS.
  - Leave the static and PNG path (`withCorn`) on the composite so exports don't change.
- Count active and drawn cells in the existing renderer stats object (`game.js:1766`).

**2. Animals: facing kept outside the save, mirrored side view**
- Facing should live in `ui.facing` only, never in `S` or `serialize`. Reset it to down (front) in `syncActors`.
- Add `pose.facing` to `drawAnimal`:
  - Down: the existing front view.
  - Up: a new back view (no face).
  - Right: a new side profile with legs swinging fore and aft.
  - Left: the right profile drawn under `scale(-1,1)` about `cx`. That's a mirror, not a rotation, and it's safe as long as no species has an asymmetric marking.
- Icons and `exportPng` pass no facing, so they stay front-facing.
- **Pitfall:** `runTo` moves up to 6 cells, and `ui.vr` eases toward the target. If facing is derived from the interpolated vector, it flickers on L-shaped slides. Set facing from the last successful step instead: compare `S.run` before and after in `act` and `pointerAct`, take the dominant axis (`core.dirIndex`), and leave it unchanged on blocked moves.

**3. Top song controls**
- Move the select and status into the header. Drive the select from `audio.nowPlaying().id`, not `audio.track()` (`game.js:1609`), so it stays correct while auto-rotate is on.
- Previous/next should call `setTrack(ids[(i ± 1 + 5) % 5])`, where `i` is the audible song. Never call `setMusic` from these controls, so changing songs can't unmute.
- **Pitfall:** right after `setTrack`, `nowPlaying()` still returns the old song until the new one's onset, so a quick second "next" goes to the same target. Keep a `pendingTrack` in the UI and step from it until `nowPlaying().id` matches it.

**4. Support links**
- Use static `<a hidden>` elements and toggle `hidden` when an action succeeds.
- **Pitfall:** `save-status` and the import error are written with `.textContent` (`game.js:1631`), which deletes any child nodes. Put each support anchor in a sibling element, never inside a status node.

**5. Mobile**
- The D-pad is already screen-relative and uses pointer capture. Don't add a stick.
- Add the following:
  - A `contextmenu` preventDefault and `-webkit-touch-callout:none` on `.dpad-btn`. Otherwise an Android long-press fires `pointercancel` and drops the hold.
  - `font-size:16px` on the header select below 620px, so iOS doesn't zoom when it's tapped.
  - `flex-wrap` on the header with no sticky positioning, so it can't cover the D-pad.
- `#field` has `touch-action:none`. Keep the canvas height below the viewport (`svh`) so phone users can still scroll the page.

**6. Tests**
- The CDP touch tests must send `touchCancel` while a button is held, and check that `ui.held` clears.

**Main tradeoff:** splitting cells into per-plant sprites costs memory and about 3× the draw calls on active cells, in exchange for the independent per-plant motion the plan asks for. The alternative worth considering is per-cell bursts that keep today's sprite: cheaper and lower-risk, but the three plants in a cell always move together.

**Risk to existing systems:** the existing sway and reduced-motion regression tests assert `amplitude: SWAY_AMP` and a continuous wave. They will need updating, so coordinate that with Codex's test lane rather than letting it show up as a failure.
