## Core model (recommended)

Add one field and make the gates nullable. Leave everything else alone.

```
S.purpose: 'art' | 'maze'          // default 'art'
S.start, S.exit: {x,y} | null      // null = not yet placed
```

- **Rules for the core functions:** `isSolvable` and `runTo` return false/0 unless purpose is `'maze'` and both gates are set. The renderer draws gates, the runner and the route HUD only under that same condition. The solver, the grid and the tractor don't change.
- **Placing a gate:** the target must be an in-bounds cell that isn't the other gate's cell. Reject it otherwise; don't swap. Placement is one history entry: `pushEntry(snapshotMeta(s))` (`game.js:143` already captures start, exit and seed), then carve the target cell with `recordCarve`. Make `snapshotMeta` and `undo` (`game.js:145`, `:160-162`) null-safe by copying `null` through. `undo` already calls `resetRun` when the layout changes (`:165`), which covers "reset run".
- **Undo:** the art/maze toggle is **not** a history entry. It's a saved view preference that never touches the grid, so undo can never flip purpose or hide work. Size changes and New both clear history behind the existing confirm. Generate stays one history entry, as it is now.
- **Serialize v2:** write `purpose`, and write `start`/`exit` as `[x,y]` or omit them. Parse v2: a gate that is present must be in bounds, cleared and distinct (`:349-353`). An absent gate becomes `null`. Parse v1 gets `purpose:'maze'` and requires gates, as today.
- **Tradeoff:** builds before v2 reject v2 files with "newer version" (`:326`). The alternative is to stay on v1 and always store placeholder gates. That avoids the version bump, but it forces art saves to carve cells the user never asked for. I recommend accepting v2.
- **Risk (HIGH):** `game.js:1218-1227`. If the stored save fails to parse (for example after a rollback, or a v2 bug), the game starts a default field and `scheduleSave()` **overwrites the user's save**. Before saving, copy the raw string to `cornfield-carver:backup` whenever `saved && !res.ok`.

## Camera changes and flashing: causes, most likely first

1. **The backing store is cleared on every observer callback.** `computeLayout` (`game.js:744`) assigns `canvas.width`/`height` unconditionally, which wipes the canvas, sets `layerDirty` and snaps the camera. The ResizeObserver (`:1131`) runs after `requestAnimationFrame` and before paint, so the cleared canvas gets painted: one blank frame. Several things trigger it:
   - `100vh`/`66vh` heights (`styles.css:75,205,222`) change when the mobile URL bar shows or hides.
   - HUD and panel text changes reflow `.stage`.
   - `window.resize` fires as well (`:1130`).
2. **Automatic close-up.** `ui.view='auto'` switches to close-up whenever `fit < 22` (`:746`). Close-up then follows the active actor (`:1174-1175`). Two effects:
   - `setMode` swaps the followed actor between tractor and runner with `snapCam=false` (`:866`), so the view glides across the field.
   - Small size changes push `fit` back and forth across 22, flipping between whole-field and close-up.
3. **Ambient effects.** Summer fireflies pulse their alpha (`:1142`), and autumn and spring particles jump between edges at `%1`. These draw over the field and read as flicker. Remove them, or skip them when `prefers-reduced-motion` is set.
4. **Pointer drift (minor).** Pointer-to-cell mapping uses the smoothed `ui.ox`/`ui.oy`, so a tap during a pan lands on a different cell. A fixed fit view removes this.
