**Recommendation:** keep everything inside the existing single rAF loop and the existing audio graph. Add three small, separately testable pieces: a cached minimap base, a per-frame gait accumulator, and a pure step-pattern function with a scheduler.

**Minimap**
- Draw the field into a small offscreen canvas at 1 px per cell (paths, plants, gates), then scale it up with `imageSmoothingEnabled=false`. Rebuild it only when `ui.layerDirty` flips (`game.js:918`, `:1371`, `:1415`). Don't downscale `ui.layer`: it's the large sprite canvas, and carving already marks it dirty on every step.
- Each frame, blit the cached base and draw only the viewport rect (from `ui.ox/oy/cw/ch`, `game.js:1421-1423`) and the active actor dot.
- **Pitfall:** the ResizeObserver watches `canvas.parentNode` (`game.js:1388`). If switching tabs changes the sidebar height and that reflows the stage on small screens, `computeLayout` can change `t`. That rebuilds the layer and the camera jumps. Give the stage a size that doesn't depend on tab panel height.

**Tabs / input**
- **Main pitfall:** the global `keydown` on `window` (`game.js:1257-1260`) runs on arrow keys and calls `preventDefault`. Arrow keys on a focused tab would also drive the tractor or runner. Add an early return when `e.target.closest('[role=tablist]')` is set, and handle Arrow/Home/End on the tablist itself.
- When the active panel is hidden while it holds focus, move focus to its tab, or focus falls to `body`.
- Settings handlers keep their IDs. A season change already only marks the layer dirty, which is correct.

**Gait**
- Each frame, add `hypot(Δui.vr)` to a stride phase. The pose comes from `sin(phase)`, not `now`, which replaces the time-based bob at `game.js:1448`.
- If the movement is under about 0.002 cells, ease the phase toward the nearest neutral pose and snap it there below a threshold. Don't freeze mid-stride.
- Ignore jumps over 1 cell (reset, `syncActors`, load) so a teleport doesn't spin the legs.
- Blocked moves never change `S.run`, so they produce no distance. The bump jig stays separate.
- With reduced motion, `k=1` (`game.js:1398`) makes `vr` jump a whole cell, so force the phase to neutral there.
- Expose `{phase, moving}` from the gait and `{rect, actor}` from the minimap through `__cornfield`.

**Music**
- Write a pure `patternAt(step)` that returns `[{voice, freq, dur, gain}]` from fixed arrays: a 16-step bar and a 4-bar progression. No `Math.random` (currently at `audio.js:70-72`). Tests can call it directly.
- Scheduler pitfalls in the current code:
  1. `startLoop` resets `nextBeat` but not `beat` (`audio.js:82`), so the loop restarts mid-bar. Reset to step 0, or round up to the next bar line.
  2. The lookahead is 0.6 s with a 200 ms interval. Turning music off then on within that window doubles notes, because the already scheduled notes still play while new ones are scheduled from `now`. Use about a 25–50 ms interval with about 0.15 s lookahead, and keep `nextBeat` when it's already in the future instead of resetting it.
  3. The shared 2400 Hz lowpass (`audio.js:41`) will kill hats and the pluck's brightness. Route percussion past it, or raise the cutoff to about 6–8 kHz.
  4. Build one noise `AudioBuffer` in `ensure()` and reuse it for snare and hat. Don't allocate one per hit.
  5. Keep per-voice cleanup through `onended`. Bounded lookahead keeps live nodes at roughly 20 or fewer.
- The existing gesture, visibility and suspend logic (`audio.js:96-127`) can stay as it is.

**Main tradeoff:** a 1 px-per-cell minimap shows less art detail, but it costs almost nothing per frame.

**Alternative worth considering:** render the minimap as a scaled `drawImage` of `ui.layer`, cached on dirty only. It looks richer but costs more memory and time on large fields.

**Risks to existing systems:**
- The global key handler stealing arrow keys (above).
- Layout-driven layer rebuilds on small screens (above).
- PNG export (`game.js:1209-1221`) must keep using the static pose, with no gait phase.
