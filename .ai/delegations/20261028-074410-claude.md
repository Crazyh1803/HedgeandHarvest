SUMMARY: I implemented the lively-farm-playlist plan in `game.js`, `audio.js`, `index.html` and `styles.css`: visible running, motion modes, swaying corn, fresh start with Continue, and five tracks. Only the Node suite ran. The browser suites and pixel checks could not run here, because this session blocks node scripts and env changes. So the new rendering, sway and startup behaviour has not been seen in a browser.

- **Running:** `drawAnimal` now draws four lower legs hanging below the body, outside its outline, with diagonal pairs alternating and the paws lifting. The body rolls and the head nods. The runner is about 0.5 tile and the stride is `d*TAU*0.4`. Settling goes to the nearest multiple of π and keeps the phase, so alternation survives taps. Icon and PNG placement were adjusted to match.
- **Motion:** `#motion-mode` offers device, full and reduced, with `#motion-note` explaining why motion is off. It follows live media-query changes. Full overrides a device reduced-motion setting.
- **Corn:** The ground layer is now cached without corn. Corn is drawn live for visible cells only, as a horizontal skew anchored at each stalk base, with a seeded wave. Reduced mode and PNG export use a baked static layer.
- **Startup and saves:** Every load opens a fresh planted field using the last size, season and animal. Boot writes nothing to `KEY`. Name, season, animal, maze toggle and size changes only write once saving has started. `#btn-resume` reopens the earlier save, with a confirmation if the current field has edits. The first real edit copies the old save to a one-deep checkpoint, and a failed checkpoint blocks saving. The invalid-save backup is kept, import and Continue clear the pending save timer, and the v1/v2 schema is unchanged.
- **Music:** Five tracks at 118 BPM, with the original arrangement preserved verbatim as `cornfield-bounce`. The original fingerprint matched the plan's SHA256, checked with a temporary test that I deleted. UI is `#music-track`, `#music-rotate` (default on) and `#now-playing`. Auto rotation runs every 256 steps (about 65s) and wraps from 5 to 1.

**Storage keys**
- `KEY` is unchanged at `cornfield-carver:v1`.
- New: `cornfield-carver:previous`, the one-deep checkpoint.
- New: `cornfield-carver:prefs:v1`, holding `{size, season, animal, motion}`.
- New: `cornfield-carver:music:v1`, holding `{track, auto}`.
- `cornfield-carver:audio:v1` now holds only `{music, sfx}`.

**API changes**
- Audio:
  - `patternAt(step)` is always the original.
  - `patternAt(step, id)` returns the named track.
  - `tracks` is `[{id, title, bpm}]`.
  - Also added: `rotationSteps`, `track()`, `setTrack(id)`, `autoRotate()`, `setAutoRotate(bool)`, `trackAt(step)` and `nowPlaying()` (returns `{id, title, playing}`).
- Game hooks:
  - Added `__cornfield.posePreview(kind, phase, amount)`, which returns a PNG data URL from `drawAnimal` on a transparent 160×160 canvas.
  - Added `__cornfield.cornMotion()`, which returns `{active, drawn, amplitude, time}`.
  - `view()` now also returns `motionMode` and `deviceReduce`.
  - `animation()` is unchanged, but the phase now stays at a multiple of π when the runner stops, instead of resetting to 0.

**Limits**
- Only one checkpoint is kept, so two fresh carvings in a row lose the oldest save. Two tabs can still race on `KEY`.
- Rotation restarts from the selected song after music is turned off and on, or after the tab has been hidden and shown again.
- Changing field size never writes `KEY`, even in maze mode. The new field is saved only on the first real edit.
- Several existing browser tests will need adapting for the fresh start. These include any that expect auto-restore, phase reset to 0, the old runner size, or sway under non-reduced motion.

TESTS: `ak-test` passes 25/25 Node tests. A temporary audio test (fingerprint, five distinct tracks, muted selection builds no audio context, rotation 3→4 after about 65s, switch cleanup) also passed and was removed. Browser suites not run, as above.
