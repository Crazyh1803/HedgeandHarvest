SUMMARY: I added optional procedural audio with separate Music and Sounds toggles, both off by default, and wired it into the existing carve, step, bump and victory actions. `ak-test` passes, but I haven't run the game in a browser, so the sound itself and the mobile header fit are unchecked.
- **Music:** a sparse, slow loop of sine/triangle notes over warm low pads, with a very soft slow pulse. It schedules about 0.6s ahead on a 200ms timer.
- **Effects:** soft short blips for carve, step, bump and victory. There is no continuous tractor sound.
- **Behaviour:** audio starts only from a toggle click. Settings are saved in a try/catch, and a saved "on" setting begins playing at the first pointer or key press. When the tab is hidden the music stops and the audio context suspends. It resumes when the tab is visible again if a toggle is on. If Web Audio is missing, both toggles are disabled and a note appears.
- **Layout:** the header buttons wrap on narrow screens.

Facade `window.CornfieldAudio`:
- `supported` is true when the browser has Web Audio.
- `music()` and `sfx()` return the current state.
- `setMusic(on)` and `setSfx(on)` change a setting and return the new state, or false if the audio context can't start.
- `carve()`, `step()`, `bump()` and `victory()` play the effects, and do nothing when Sounds is off or the context isn't running.
- `onChange(fn)` calls `fn` whenever a setting changes.
