SUMMARY: I built the full cozy Cornfield Carver, but only the Node-testable core was run. The Canvas rendering and DOM controller (about two-thirds of `game.js`) have never run in a browser and need the desktop and phone smoke checks. The core is in `game.js` and exports for Node: seeded maze generation, tractor carving, runner collision and exit victory, bounded undo, and versioned JSON export/import with bounds and type checks that never run imported code. Everything else is drawn in code, including the scalloped corn clusters on a raised tray, the top-down toy tractor and the six animal avatars. Local autosave, PNG export and the confirm dialogs for destructive actions are also in.
FILES: index.html, styles.css, game.js, tests/game.test.cjs
TESTS: `ak-test` passes, 14 of 14. They cover:
- maze solvability for 3 sizes × 4 seasons × 12 seeds
- JSON round-trip, and rejection of bad or hostile imports
- runner collision and winning at the exit
- carve and undo, including stroke grouping, the 150-step limit, and undo of maze regeneration and replanting
- the hint route
OPEN QUESTIONS:
- The DOM controller still has to be smoke-tested in a browser: rendering, pointer and touch input, the dialogs, PNG download, and the layout on desktop and phone.
- A syntax check on `game.js` was blocked by permissions, but the tests parse the whole file, so it is syntactically valid.
- Switching season only changes the look and the maze style used for later mazes; it doesn't rebuild the current maze.
- The PNG export doesn't embed the JSON. Sharing a field means sending the JSON file or text separately.
- On first load a localStorage save is restored; otherwise a medium summer maze with the dog is shown. I added a `window.__cornfield` debug hook, which you may want to remove.
